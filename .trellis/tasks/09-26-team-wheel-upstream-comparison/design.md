# 技术设计：安全顶部锚点与可观察滚动

## 范围与边界

共享选队入口 `tasks/teams/team_formation.py`，纯 OCR 页模型 `tasks/team_list.py`，Windows 后台输入 `module/automation/input_handlers/input.py`；日常和镜牢只消费 True/False，保持现有失败传播。两套 G 盘发行版仅作为只读证据，不改配置、存档或可执行文件。

## 决策与数据流

1. 读取同一截图中的 OCR 条目及列表几何。按顺序选队在“固定首项文本明确、位于最上缘、列表逐行连续、目标行可见”时，可直接以该行作为顺序锚点，无须进行下滚探针。以当前用户画面为例，第 1 项是“剧情关卡”，第 2 项是“编队#2”；不能用上方当前选队标题替代列表首项证据。按名称编号模式保留当前页唯一命中快捷路径。
2. 不满足顶部锚点条件时，保留有限归顶/翻页与 OCR 位移确认；每次输入仅承诺尝试，后续截图的位置/条目变化才算滚动。优先调查 Windows 后台 `WM_MOUSEWHEEL` 在这台游戏是否生效；若需要替代手势，必须在受控真实游戏中确认起点不在可重排条目上、实际列表位移且顺序不变，才能纳入自动回退。没有被证明安全的替代方式时返回 False 并留下截图，而不是猜第 N 项或调用旧拖动。
3. 点击目标后，重截并只从顶部当前编队标题验证选中身份；重试、识别失败与异常均有限退出。调用方收到 False 不进入战斗或镜牢确认。
4. 镜牢 `select_mirror_team()` 等星光页的确认循环耗尽或 `retry() is False` 时抛出 `cannotOperateGameError`；`onetime_mir_process()` 捕获并返回 False，阻止后续成功收尾，成功进入星光页保持既有路径。日常的单场→组→顶层 False 传播不变。

## 取舍

直接恢复上游长按拖动虽能推进本次游戏，却可能更改用户队伍顺序且无法核验；禁止此回退。对已归顶且目标可见的状态采用可验证的顶部固定项，能消除本次失败；对于中途滚动过的画面，优先安全检测和可观察进展而非虚假完成。后台消息的真实消费行为不能由 mock 单测证明，需独立记录实机结果。

## 兼容与回滚

保留原配置语义、40 只是队伍编号上界、模拟器滚动方案和固定的失败上限。按顺序的固定首项锚点仅在明确识别时启用；其他语言、OCR 模糊、重名或列表非顶部均保持安全失败或经过验证的滚动。代码变更局限于共享选队及必要的输入适配，回滚点为独立的选队行为提交；不直接部署到 G 盘。
